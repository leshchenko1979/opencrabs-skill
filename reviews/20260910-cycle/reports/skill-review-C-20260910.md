### EXECUTIVE SUMMARY

This audit evaluates the tool surface of `opencrabs-dev` v0.4.132 against actual runtime invocations, exit code distributions, error patterns, manual operator rituals, and process discipline compliance.

Key systemic findings:
1. **Adoption Compliance / One-Watcher Law Breaches**: Editors continue to detach `gh run watch` directly rather than routing through `oc-waiter arm` and atomic checks.
2. **Subcommand & Flag Inconsistencies**: Recurring exit code 2 (CLI syntax / usage error) spikes across `oc-waiter`, `oc-ledger`, and `oc-prchecks` due to flag naming mismatches (`--deadline` vs `--timeout`, `--issue` vs positional args).

4. **Automation Opportunities**: Multi-step fanout lock recovery and worktree tracking rituals lack first-class CLI verbs.

### PART A: RECURRING MANUAL RITUALS & CLI AUTOMATION GAPS

#### Finding C5-A1: Manual Lock & State Reconcile Ritual on `oc-notify-fanout` Interruption
- **Severity**: MED
- **Citation**: `/root/.opencrabs/profiles/ops/skills/opencrabs-dev/tools/oc-notify-fanout:140-165`, `/root/.opencrabs/profiles/ops/skills/opencrabs-dev/run/`
- **Pattern**: When `oc-notify-fanout` fails midway through a wave or is aborted by session timeout/SIGINT, the state lock file (`run/wave-<id>.lock`) remains on disk. Lanes perform a recurring 3-step manual ritual:
  1. Inspecting `/run/wave-*.sent` to see who was missed.
  2. Removing `/run/wave-*.lock` manually via shell.
  3. Reconstructing the residual recipient list by hand.
- **Proposal**: Add `oc-notify-fanout unlock <wave-id>` and `oc-notify-fanout resume <wave-id>` to reconcile target lists against `.sent` markers automatically and clear stale locks safely.

#### Finding C5-A2: Manual Multi-Step Worktree Remote Branch Setup
- **Severity**: LOW
- **Citation**: `/root/.opencrabs/profiles/ops/skills/opencrabs-dev/tools/oc-wt:214-285`, `tools.log:144-148`
- **Pattern**: When creating temporary worktrees for remote branches, operators run `git fetch` -> `oc-wt add` -> manual upstream tracking fixups because `oc-wt add` expects a local branch or defaults to detached HEAD without tracking.
- **Proposal**: Introduce `--track <remote>/<branch>` flag in `oc-wt add` that fetches and configures branch tracking in a single atomic invocation.

### PART B: TOOL PARAMETERIZATION & ERROR MESSAGING GAPS

#### Finding C5-B1: Parameter Syntax Inconsistencies Leading to Exit Code 2 Thrash
- **Severity**: HIGH
- **Citation**:
  - `tools.log:7271` (`oc-waiter arm ... --deadline-mins 30` -> `exit: 2`)
  - `tools.log:7272` (`oc-waiter arm ... --timeout 30m` -> `exit: 0`)
  - `tools.log:7302` (`oc-waiter arm --run 34425703673 --ref fb31da1c --label 144shipchain-gate` -> `exit: 2` missing `--timeout`/`--notify`)
  - `tools.log:7306-7307` (`oc-ledger append --type confirm ...` / `oc-ledger confirm ...` -> `exit: 2`)
- **Evidence**:
  - `oc-waiter` rejects `--deadline-mins` or missing `--timeout`/`--notify` without an actionable one-line syntax reminder.
  - `oc-ledger` has had its subcommands modified across versions, causing repeated trial-and-error CLI invocations (`confirm --help`, `confirm`, `stamp --type confirm`) in active ship loops.
- **Proposal**:
  1. Implement lenient flag aliases (`--deadline` / `--timeout` / `--deadline-mins`) in `oc-waiter`.
  2. Add structured usage hints on RC 2 errors pointing directly to the required flag set.

#### Finding C5-B2: Missing `OC_ACTOR` Context in Subagent / Sub-shell Invocations
- **Severity**: LOW
- **Citation**: `tools.log:7242`, `tools.log:7308`, `/root/.opencrabs/profiles/ops/skills/opencrabs-dev/tools/lib/oc-log.sh:35-42`
- **Evidence**: Multiple entries in `tools.log` record `"actor":"unknown"` when tools are invoked from sub-shells where the parent environment did not export `OC_ACTOR` or `OPENCRABS_SESSION_ID`.
- **Proposal**: Update `lib/oc-log.sh` to fall back to probing `~/.opencrabs/profiles/ops/current-session` or checking git config `user.signingkey`/email before writing `"unknown"`.
