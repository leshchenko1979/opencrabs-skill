### [HIGH] E-1: Environment Variable Semantic Collision on `OC_GIT`
- **Location:** 
  - `/root/.opencrabs/profiles/ops/skills/opencrabs-dev/tools/oc-upstream-delta:31`
  - `/root/.opencrabs/profiles/ops/skills/opencrabs-dev/tools/oc-seal-state:45`
- **Verbatim Quotes:**
  - `oc-upstream-delta:31`:
    ```bash
    GIT_BIN="${OC_GIT:-git}"
    ```
  - `oc-seal-state:45`:
    ```bash
    GIT="${OC_GIT:-/root/opencrabs}"
    ```
- **Analysis:**  
  `OC_GIT` is overloaded with two mutually incompatible semantics across the tools suite:
  1. In `oc-upstream-delta`, `OC_GIT` designates the git binary name/path (defaulting to `"git"`).
  2. In `oc-seal-state`, `OC_GIT` designates the repository directory path (defaulting to `"/root/opencrabs"`).
  If an operator or subagent exports `OC_GIT` pointing to an alternative git binary (e.g. `/usr/bin/git`), `oc-seal-state` treats it as a repository checkout path and fails git operations (`not a git repository`). Conversely, exporting `OC_GIT=/path/to/repo` causes `oc-upstream-delta` to execute the directory path as a binary, yielding `Permission denied` / `command not found`.
- **Classification:** **HIGH**
- **Recommendation:** Rename `oc-seal-state:45`'s variable to `OC_REPO` or `OC_CLONE` (e.g., `GIT="${OC_CLONE:-/root/opencrabs}"`).
